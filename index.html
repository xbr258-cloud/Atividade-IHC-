Protótipo de IHC

GitHub Issues sem filtro punitivo por comando

Refatoração de uma busca complexa para menus visuais e manipulação direta.

Sistema real usado: GitHub
Antes

Busca por linguagem de comando

No GitHub, o usuário pode filtrar issues digitando operadores como is:issue, state:open, label:bug, assignee:@me e combinações booleanas.

Erro comum: esquecer dois-pontos, digitar label errado ou misturar filtros sem entender a sintaxe.

Pontos de alta memória de trabalho

  • O usuário precisa lembrar os nomes exatos dos qualificadores.
  • Precisa saber a ordem lógica dos filtros e como combiná-los.
  • Precisa traduzir uma intenção visual simples para texto técnico.
  • O erro aparece depois da tentativa, não durante a escolha.
Depois

Filtro visual por menus e cartões

O mesmo objetivo foi mantido, mas agora o usuário escolhe opções reconhecíveis e organiza a busca sem decorar comandos.

Justificativa técnica

A solução original do GitHub depende de uma linguagem de comando com qualificadores e operadores que exigem recordação ativa, como lembrar nomes, dois-pontos, valores aceitos e combinações possíveis. Na refatoração, a mesma tarefa foi convertida em menus visuais, cartões de filtros e pré-visualização automática da consulta, reduzindo a distância físico-cognitiva porque o usuário deixa de transformar mentalmente sua intenção em sintaxe textual e passa a reconhecer opções já disponíveis na interface. Antes, a carga de memória ficava no usuário; depois, ela passa para a própria interface, que apresenta as escolhas, impede combinações mais confusas e mostra o resultado gerado em tempo real.
